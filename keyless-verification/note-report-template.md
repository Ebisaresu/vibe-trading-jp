# note 日次レポート生成指示書（テンプレート）

毎営業日、このファイルの指示どおりに note 投稿用レポートを生成する。
実行者（LLM エージェント）への指示書であり、レポート本文ではない。

## 実行条件

- **実行時刻: 17:00 JST 以降**（大引けは 15:30。TDnet の開示は 15:30 ちょうどと 16:00 に集中し、17:00 まで続くため。15:30 直後の実行では当日の開示を取りこぼす）
- 出力先: `keyless-verification/note-daily-YYYY-MM-DD.md`
- 実行環境（APIキーゼロを空環境で保証する）:

```bash
cd /home/mtforestlab/projects/vibe-trading && env -i HOME=$HOME PATH=/usr/bin:/bin \
  ./.venv/bin/python -c "import sys; sys.path.insert(0,'agent'); ..." \
  2>&1 | grep -v 'WARNING\|INFO\|请设置\|falling back'
```

- 執筆ルールの原典: `agent/src/skills/japan-market/SKILL.md` を先に読むこと

## データ収集（すべてキーレス）

| データ | 呼び出し |
|---|---|
| 指数・FX・商品・主要個別 | `src.market_data.fetch_market_data(codes=[...], start_date=30日前, end_date=当日, max_rows=0)` — `^N225` `1306.T` `^GSPC` `^IXIC` `^DJI` `^VIX` `^HSI` `^TNX` `USDJPY=X` `EURJPY=X` `GC=F` `CL=F` + 主要8銘柄程度 |
| 騰落・売買代金 | `MarketScreenerTool().execute(market='jp', sort_by='amount', top_n=15)` |
| 値上がり率上位 | 同 `sort_by='change_pct'` |
| 本日の決算短信 | `JapanEarningsTool().execute(mode='disclosures', kind='earnings', limit=40)` |
| 業績予想の修正 | 同 `kind='guidance', limit=50` — **全件リスト化する（本レポートの差別化の核）** |
| 営業日の確認 | 同 `mode='trading_days', date=当日` — 当日が営業日か、前営業日・翌営業日の日付、今後30日の休場日 |
| 翌営業日の決算予定 | 同 `mode='calendar', codes=[注目銘柄]` — `is_estimate` を必ず確認。`on_closed_day` が付いた日付は休場日なので予定として書かない |
| 動いた銘柄のニュース | `StockNewsTool().execute(code=..., limit=6)` を2〜4銘柄 |

## タイトルの型

`【M/D日本株】<本日の結論を数字入りで一行>——<引きになる問い>`

例: `【8/7日本株】日経▲0.4%でも騰落レシオ2.3倍——半導体安の裏で何が買われたか`

## 構成（この順序・この有料ライン位置を固定）

### 無料部分（全体の3〜4割）

**冒頭**: 取得時刻と「全数値はAPIキーゼロの一次ソース当日取得」の一行。

**０．3行サマリ** — 結論先出し。3行目は有料部分への引き
（例:「業績予想の上方修正は41件。全リストは後半に」）。

**１．市況ダッシュボード** — 主要指標テーブル（終値・前日比・備考）+ 騰落概況。
コモディティ情報はここで出し切る。無料部分の質が購入率を決める。

**２．今日の構図** — 指数・マクロ層のみ。日経/TOPIXの乖離、ドル円、
前日米市場との接続、金利・商品。個別銘柄の深掘りはここではしない。

### ── 有料ライン ──

本文に `━━━━━ ここから有料部分 ━━━━━` の行を置く（note 投稿時にこの位置へ有料ラインを設定）。

**３．動いた銘柄の解剖** — 個別層。ストップ高安の判定（値幅制限の計算根拠を書く）、
開示時刻×値動きの突合、「材料出尽くし」の識別、ノイズの切り分け
（直近20日平均レンジ未満の動きはノイズと明記）。

**４．決算・開示ダイジェスト** — TDnet 全件の分類件数（総数・短信・予想修正・訂正）+
**業績予想の修正の全銘柄リスト**（時刻・コード・銘柄名・表題の要点）。
（訂正）は新規決算にカウントしない。

**５．翌営業日の注目** — 決算発表予定（`is_estimate` で確定/推定を明記）、
監視すべき水準（当日データから導けるものだけ。例: ドル円158円、日経の当日安値）。
翌営業日の日付と休場日は `mode='trading_days'` の返り値を使う（連休前は「翌営業日」が数日先になる）。

**６．シナリオ** — メイン/リスクの2本。各シナリオに必ず**乗り換え条件**を付ける
（「◯◯になったらこの見立ては捨てる」）。断定予測・目標株価・個別銘柄の
売買推奨は書かない。

**７．答え合わせ** — 前日レポートのシナリオを検証。的中も外れも書く。
外れた場合は「どの乗り換え条件が作動したか」を書く。
初回のみ「本日の見立て（明日から検証開始）」とする。
前日ファイル: `keyless-verification/note-daily-<前営業日>.md` を読むこと。前営業日の日付は `mode='trading_days'` の `previous_trading_day`。

**末尾（固定文）**:

> ---
> **データの前提**: 本レポートの数値はすべて公開一次ソース（Yahoo Finance / JPX /
> TDnet / kabutan）から当日取得。取得できない指標（TOPIX指数値・日経VI・
> 投資部門別売買状況など）は推測で埋めず「取得不可」と明記する方針です。
>
> **免責事項**: 本レポートは情報提供のみを目的としており、特定の金融商品の
> 売買を勧誘・助言するものではありません。投資判断はご自身の責任で
> 行ってください。掲載情報の正確性・完全性は保証されません。

## ハードルール（品質の生命線）

1. **書く数字は全部、自分が実行したツール呼び出しの返り値**。記憶・推測での穴埋め禁止
2. TOPIX 指数値はキーレス取得不可 → `1306.T` を「ETFプロキシ」と明記して使う。**NT倍率は算出しない**
3. 騰落は概算 → 母数（coverage）と as-of を必ず併記
4. 値幅制限到達は騰落率でなく「ストップ高/安」として記述し、制限幅の計算を示す
5. 動きと原因を分離 → 取得した見出し・開示が因果を明言する場合のみ因果を書く
6. 直近20日平均レンジ未満の動きはノイズと明記
7. `get_options_chain` の空返却は「データなし」であり「取引なし」ではない
8. kabutan 見出しは出典・日時付き引用の範囲で
9. シナリオは条件付き。「必ず」「確実に」等の断定的判断の提供は禁止
10. 有料部分に入れる価値の基準: 「無料メディアで同日中に同じ粒度が手に入るか？」— 入るものは無料部分へ
