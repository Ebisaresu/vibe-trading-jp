# note 記事作成ルール（日次記事・会社別メモ 共通）

記事を書く人（人でも LLM エージェントでも）への規則集。日次記事の手順そのものは
[`keyless-verification/note-report-template.md`](../keyless-verification/note-report-template.md)、
会社別メモの手順は `agent/src/skills/japan-equity-research/SKILL.md` にある。
このファイルは、その2つにまたがる「何を・いつ・どの形で出すか」を決める。

2026-10-10 確定、2026-10-11 に note 版の骨子(第5節・第11節)を追加、同日のレビュー会(`reviews/2026-10-11_9983_review.md`)を受けて第4〜7節と第12節を改定。変更するときはこのファイルを直してから記事の形を変える。

## 1. 記事は2種類。役割を混ぜない

| | 日次記事 | 会社別メモ |
|---|---|---|
| キー | 日付 | 会社 × 決算期 |
| 読者 | 定期読者。市況の流れと「答え合わせ」の連続性 | 検索で来る読者。その会社の決算の中身 |
| 寿命 | 翌日まで | 次の決算まで（約3か月） |
| 深さ | 広く浅く。業績予想の修正は全件 | 1社を深く。増益の内訳が合計と一致する表まで |
| 継続の仕組み | 前日のシナリオの答え合わせ | 前回メモの「仮説の確認項目」の答え合わせ |

- 日次記事で1社を深掘りしない。決算のあった日は、有料部分に「3行サマリ」と会社別メモへのリンクだけを置く。
- 会社別メモで市況を語らない。同日の指数は株価反応の比較対象としてだけ出す。

## 2. 会社別メモを書く条件

次のどれかに当てはまる決算を独立記事にする。決算集中期でも1日1〜2本に収まる線引き。

1. 予定表で追っている銘柄（TOPIX Core30 を基本とし、追加・除外はこのファイルの末尾の一覧に書く）
2. 業績予想の修正、または配当予想の修正を伴った決算
3. 翌営業日の株価の反応が、直近20営業日の前日比の絶対値平均を超えた決算

当てはまっても書かない場合（人手が足りない等）は、日次記事に「会社別メモなし」と一言書く。黙って落とさない。

## 3. 時刻と締め切り

| 記事 | 執筆開始 | 公開の目安 | 理由 |
|---|---|---|---|
| 日次記事 | 当日 17:00 以降 | 当日中 | TDnet の開示は 15:30 と 16:00 に集中し 17:00 まで続く |
| 会社別メモ | 開示当日に決算短信を保存。執筆は翌営業日 17:00 以降 | 翌営業日中に完成版を1回で公開 | 株価の反応（第4節）は翌営業日の取引で出る。開示当日は日次記事に3行サマリとリンクだけを載せ、メモ本体は反応を入れて出す |

- 決算短信の保存は開示当日に必ず行う（`jp_earnings(mode="fetch")`）。TDnet は約39日で消える。
- 前回の会社予想が TDnet から消えている場合は、会社の決算説明資料（会社サイト）で補う。出典に書く。

## 4. タイトルの型

| 記事 | 型 | 例 |
|---|---|---|
| 日次記事 | `【M/D日本株】<結論を数字入りで一行>——<引きになる問い>` | `【8/7日本株】日経▲0.4%でも騰落レシオ2.3倍——半導体安の裏で何が買われたか` |
| 会社別メモ | `【決算メモ】<会社名>(<コード>)<矛盾や意外さを一行> — <結論を数字入りで一行>` | `【決算メモ】ファーストリテイリング(9983)最高益でも翌日−4% — 海外ユニクロが利益の6割、今期の純利益は+3%の計画` |

会社別メモの題名に会社名とコードを必ず入れる。検索で見つかる唯一の手がかりになる。期の表記(「2026年8月期 通期」)は本文に回し、題名には入れない。株探と同じ見出し(「5期連続最高益」など)は引きにならないので、先頭には矛盾や意外さ(「最高益でも翌日−4%」)を置く。

## 5. 構成と有料ラインの位置

### 日次記事

`note-report-template.md` のとおり。無料は 0〜2 節（3行サマリ・市況ダッシュボード・今日の構図）、有料は 3 節以降。

### 会社別メモ

| 節 | 内容 | 無料/有料 |
|---|---|---|
| 0 | 3行サマリ | 無料 |
| 1 | 実績（通期または四半期の表） | 無料 |
| — | 「有料部分で分かること」の箇条書き(3〜5項目)、続けて `━━━━━ ここから有料部分 ━━━━━` の行 | |
| 1 | 何と比べて良かったのか（会社予想との差、アナリスト予想との差） | 有料 |
| 2 | 増益の内訳（合計が一致する表）、地域別、円安の寄与、四半期単独 | 有料 |
| 3 | 財政状態・キャッシュフロー・配当 | 有料 |
| 4 | 株価の反応（値幅制限とノイズの判定つき） | 有料 |
| 5 | 今期の会社予想と前提 | 有料 |
| 6 | 仮説の確認項目と「見立てを捨てる条件」 | 有料 |
| 7 | 次の予定、次回メモの案内 | 有料 |
| — | 出典・免責 | 有料部分の末尾 |

有料ラインの判断基準は日次記事と同じ。「無料メディアで同日中に同じ粒度が手に入るか」。
見出しの数字（売上・利益・増減率）は株探が同日に出すので無料。
会社予想との比較、内訳の分解、確認項目は手に入らないので有料（2026-10-11 決定）。
第4節の算出値（会社予想1株利益に対する倍率、配当利回り、1株純資産に対する倍率）は、計算根拠を示した参考値として載せ、指標の名前を付け、水準の高低の評価は書かない。

**無料部分に書いてよい範囲（2026-10-11 レビュー会で決定）**: 実績の額と増減率、配当、翌営業日の騰落率(一つの数字)まで。
次は有料側: アナリスト予想との差、会社予想との差の内訳、寄り付きと終値の関係、出来高の倍率、市場との対比、増益の内訳、確認項目。
3行サマリは「結論」ではなく「問い」で終える(例:「実績は会社予想を上回ったのに翌日−4.0%」)。

**「有料部分で分かること」の箇条書き**: 項目名の羅列ではなく、読者が得るものを書く。各項目は「問い＋答え方」の形(例:「なぜ翌日−4.0%だったのか。材料視された数字を特定する」「事業利益+15.5%なのに純利益+3.2%の今期計画を、税率と非支配持分の算術で説明する(会社資料には書かれていない)」)。

## 6. 相互参照

- 日次記事 → 会社別メモ: 決算のあった日の有料部分に、会社名・3行サマリ・メモへのリンク。メモは翌営業日に出るので、当日は「翌営業日に会社別メモを公開予定」と書き、公開後にリンクを追記する。
- 会社別メモ → 日次記事: 第4節（株価の反応）で、当日の日次記事へのリンク。
- 会社別メモ → 前回の会社別メモ: 第6節の冒頭で、前回の確認項目がどうなったかを書く。初回は「初回のため前回なし。次回は＜時期＞の＜四半期＞で答え合わせ」。
- 会社別メモ → 次回: 第7節の末尾に「次回のメモは＜時期＞に、確認項目の答え合わせから始める」の1行。記事は単体で閉じる構成にし、マガジンへのリンクや購読の勧誘は書かない(2026-10-11 決定)。
- 有料ラインの直後に「先に結論」の箇条書き(3〜4項目)を置く。答えを先に出し、各節はその裏付けとして読める順にする(2026-10-11 第2回レビュー会で決定)。

## 7. 書いてよいこと・書かないこと（両記事共通のハードルール）

1. 書く数字はすべて、自分が実行したツール呼び出しの返り値か、保存した開示資料の記載。記憶・推測で埋めない。
2. 格付け、目標株価、売買の推奨、持ち高の提案は書かない。ツールが返すアナリストの目標株価も転記しない。
3. 「必ず」「確実に」などの断定は使わない。シナリオには乗り換え条件を付ける。
4. 比較の基準は会社予想が主、アナリスト予想は従。アナリスト予想には人数を併記する。
5. 分解した表は合計が一致するまで公開しない。
6. 値幅制限に到達した動きは騰落率でなく「ストップ高/安」と書き、制限値幅の計算を示す。
7. 直近20営業日の前日比の絶対値平均を下回る動きはノイズと明記する。
8. 推定の日付（`is_estimate`）は、出すたびに「推定」と付ける。休場日に当たる推定日は書かない。
9. TOPIX の指数値はキーレスで取れない。`1306.T` を「上場投資信託によるプロキシ」と明記して使う。NT倍率は出さない。
10. 動きと原因を分ける。取得した見出しや開示が因果を明言する場合だけ因果を書く。
11. （訂正）の開示は新規の決算に数えない。
12. 取得できなかった情報は記事に書かない(2026-10-11 決定。読者には不要)。原稿には `<!-- note:skip -->` を付けた内部の節として残し、整形で落とす。本文で「開示に説明がない」と書くのは、その欠落自体が分析上の論点になる場合だけ(例: 今期の税率の前提)。
13. 開示資料の PDF は公開リポジトリに置かない。リンクは TDnet のものを貼り、期限があることを書く。
14. 末尾に固定の免責事項を置く（文面は下記。`note-report-template.md` も同じ）。筆者が当該銘柄を保有しているかは記事ごとに書く。
15. 「見立て」という語を使う節では、冒頭でその意味を定義する。会社計画の前提が成り立っているかを確かめる意味であり、保有や売買の判断基準ではないと明記する。「見立てを捨てる条件」ではなく「会社計画の前提が崩れたとみなす条件」と書く。
16. 「初めて」「過去最高」「○期連続」のような過去全体についての断定は、会社資料に記載がある場合だけ使い、出典を付ける。会社資料からの鉤括弧引用には資料名とページを付け、要約なら鉤括弧を使わない。
20. 逆算や分解は、同じ次元の数字どうしで行い、答えが一意でないときはその旨と代替の組み合わせを書く。比較の基準(前期か、会社予想か)を明示する。
21. 貸借対照表の増減(在庫など)を伸び率として論じるときは、キャッシュフロー計算書の増減額で換算の影響を除いた値を併記する。
22. 初出の専門用語(非支配持分、配当性向、既存店売上、棚卸資産など)には括弧で一言の説明を付ける。
17. 推論は推論と書き、引用した見出しの因果と筆者の因果を一文に接合しない。見出しが挙げる要因と、筆者が数字から読む要因を分けて書く。
18. 出典欄には取得日時を付け、使った媒体(TDnet、会社サイト、Yahoo Finance、株探、JPX)をすべて列挙する。
19. コメント欄・メンバーシップで個別の売買相談には答えない。

## 11. note 版の骨子と整形の規約

原稿（Markdown）が正。note に貼る版は `scripts/note_export.py` で毎回作り直す。

### 会社別メモの note 版

| 位置 | 節 | 形 |
|---|---|---|
| 無料 | リード（取得日時と一次ソースの一文） | 本文2行 |
| 無料 | 0. 3行サマリ | 箇条書き3つ |
| 無料 | 1. 実績の表 | 画像 + 本文 |
| 無料 | 予告（有料部分で扱う内容を1行） | 本文1行 |
| 有料 | 1. 何と比べて良かったのか | 画像 |
| 有料 | 2. 増益の内訳・売上の内訳・地域別・円安の寄与・四半期単独 | 画像3枚 + 本文。四半期単独は箇条書き |
| 有料 | 3. 財政状態（箇条書き）・配当の推移（画像） | |
| 有料 | 4. 株価の反応。値幅制限・ノイズ・市場との対比の3判定は太字 | 箇条書き |
| 有料 | 5. 今期の会社予想（画像）と前提（箇条書き） | |
| 有料 | 6. 前回の答え合わせ、確認項目（画像）、見立てを捨てる条件 | |
| 有料 | 7. 次の予定 / 8. 取得できなかったもの / 出典 / 免責 | 箇条書き・固定文 |

画像は8枚前後。分量は本文2,500〜3,500字、無料部分は1,000字前後。

### 整形の規約（原稿の書き方）

- note は表を描画しないので、表は画像にする。既定では**データ行が4行以上の表を画像**、3行以下は「項目: 値」の箇条書きにする。
  表の直前の行に `<!-- note:image -->` または `<!-- note:list -->` を置けば既定を上書きできる。
- 画像にする表の直後には、`要約:` で始まる1行を書く（画像が読めない人向け。例: `要約: 営業利益の増加1,789億円のうち海外ユニクロが78%`）。無い場合、整形後の出力に `【要約を書く】` が残る。
- 文章の多い表(確認項目など)は `<!-- note:cards -->` を付け、画像ではなく「1行＝1ブロック」の本文にする(見出しは太字、残りの列は「列名: 値」の箇条書き)。スマートフォンで横長の画像は読めない。
- 箇条書きにする表の括弧内は列名をそのまま使うので、列名は読者向けに付ける(「根拠」ではなく「補足」)。
- 内部の節(取得できなかったもの、作業メモ)は見出しの直前に `<!-- note:skip -->` を置く。次の同じ階層の見出しまで落ちる。
- 整形後の出力に `【` が残っていたら未記入(要約、保有の有無)。整形スクリプトが件数を報告する。
- 次の行は整形時に落とす: `作成:` `手順:` `同日の日次記事:` `前回の会社別メモ:` で始まる行、`保存済み` を含む出典の行。
- `━━━━━ ここから有料部分 ━━━━━` は `（ここに有料ラインを設定）` に置き換える。
- 題名（先頭の見出し）は本文から外し、出力の先頭に「題名:」として別に出す。
