# note 記事作成ルール（日次記事・会社別メモ 共通）

記事を書く人（人でも LLM エージェントでも）への規則集。日次記事の手順そのものは
[`keyless-verification/note-report-template.md`](../keyless-verification/note-report-template.md)、
会社別メモの手順は `agent/src/skills/japan-equity-research/SKILL.md` にある。
このファイルは、その2つにまたがる「何を・いつ・どの形で出すか」を決める。

2026-10-10 確定。変更するときはこのファイルを直してから記事の形を変える。

---

## 1. 記事は2種類。役割を混ぜない

| | 日次記事 | 会社別メモ |
|---|---|---|
| キー | 日付 | 会社 × 決算期 |
| 読者 | 定期読者。市況の流れと「答え合わせ」の連続性 | 検索で来る読者。その会社の決算の中身 |
| 寿命 | 翌日まで | 次の決算まで（約3か月） |
| 深さ | 広く浅く。業績予想の修正は全件 | 1社を深く。増益の内訳が合計と一致する表まで |
| 継続の仕組み | 前日のシナリオの答え合わせ | 前回メモの「仮説の確認項目」の答え合わせ |

- 日次記事で1社を深掘りしない。決算のあった日は、有料部分に「3行サマリ」と会社別メモへのリンクだけを置く。
- 会社別メモで市況を語らない。同日の指数は株価反応の比較対象としてだけ出す。

## 2. 会社別メモを書く条件

次のどれかに当てはまる決算を独立記事にする。決算集中期でも1日1〜2本に収まる線引き。

1. 予定表で追っている銘柄（TOPIX Core30 を基本とし、追加・除外はこのファイルの末尾の一覧に書く）
2. 業績予想の修正、または配当予想の修正を伴った決算
3. 翌営業日の株価の反応が、直近20営業日の前日比の絶対値平均を超えた決算

当てはまっても書かない場合（人手が足りない等）は、日次記事に「会社別メモなし」と一言書く。黙って落とさない。

## 3. 時刻と締め切り

| 記事 | 執筆開始 | 公開の目安 | 理由 |
|---|---|---|---|
| 日次記事 | 当日 17:00 以降 | 当日中 | TDnet の開示は 15:30 と 16:00 に集中し 17:00 まで続く |
| 会社別メモ | 開示当日に決算短信を保存。執筆は翌営業日 17:00 以降 | 翌営業日中に完成版を1回で公開 | 株価の反応（第4節）は翌営業日の取引で出る。開示当日は日次記事に3行サマリとリンクだけを載せ、メモ本体は反応を入れて出す |

- 決算短信の保存は開示当日に必ず行う（`jp_earnings(mode="fetch")`）。TDnet は約39日で消える。
- 前回の会社予想が TDnet から消えている場合は、会社の決算説明資料（会社サイト）で補う。出典に書く。

## 4. タイトルの型

| 記事 | 型 | 例 |
|---|---|---|
| 日次記事 | `【M/D日本株】<結論を数字入りで一行>——<引きになる問い>` | `【8/7日本株】日経▲0.4%でも騰落レシオ2.3倍——半導体安の裏で何が買われたか` |
| 会社別メモ | `【決算メモ】<会社名>(<コード>)<期> — <結論を数字入りで一行>` | `【決算メモ】ファーストリテイリング(9983)2026年8月期 通期 — 5期連続最高益、海外ユニクロが利益の6割に` |

会社別メモの題名に会社名とコードを必ず入れる。検索で見つかる唯一の手がかりになる。

## 5. 構成と有料ラインの位置

### 日次記事

`note-report-template.md` のとおり。無料は 0〜2 節（3行サマリ・市況ダッシュボード・今日の構図）、有料は 3 節以降。

### 会社別メモ

| 節 | 内容 | 無料/有料 |
|---|---|---|
| 0 | 3行サマリ | 無料 |
| 1 | 実績と比較対象（会社予想との差、アナリスト予想との差） | 無料 |
| — | `━━━━━ ここから有料部分 ━━━━━` の行を置く | |
| 2 | 増益の内訳（合計が一致する表）、地域別、円安の寄与、四半期単独 | 有料 |
| 3 | 財政状態・キャッシュフロー・配当 | 有料 |
| 4 | 株価の反応（値幅制限とノイズの判定つき） | 有料 |
| 5 | 今期の会社予想と前提 | 有料 |
| 6 | 仮説の確認項目と「見立てを捨てる条件」 | 有料 |
| 7 | 次の予定 | 有料 |
| 8 | 取得できなかったもの | 有料 |
| — | 出典・免責 | 有料部分の末尾 |

有料ラインの判断基準は日次記事と同じ。「無料メディアで同日中に同じ粒度が手に入るか」。
見出しの数字（売上・利益・増減率）は株探が同日に出すので無料。
内訳の分解、会社予想との比較、確認項目は手に入らないので有料。

## 6. 相互参照

- 日次記事 → 会社別メモ: 決算のあった日の有料部分に、会社名・3行サマリ・メモへのリンク。メモは翌営業日に出るので、当日は「翌営業日に会社別メモを公開予定」と書き、公開後にリンクを追記する。
- 会社別メモ → 日次記事: 第4節（株価の反応）で、当日の日次記事へのリンク。
- 会社別メモ → 前回の会社別メモ: 第6節の冒頭で、前回の確認項目がどうなったかを書く。初回は「初回のため前回なし」。

## 7. 書いてよいこと・書かないこと（両記事共通のハードルール）

1. 書く数字はすべて、自分が実行したツール呼び出しの返り値か、保存した開示資料の記載。記憶・推測で埋めない。
2. 格付け、目標株価、売買の推奨、持ち高の提案は書かない。ツールが返すアナリストの目標株価も転記しない。
3. 「必ず」「確実に」などの断定は使わない。シナリオには乗り換え条件を付ける。
4. 比較の基準は会社予想が主、アナリスト予想は従。アナリスト予想には人数を併記する。
5. 分解した表は合計が一致するまで公開しない。
6. 値幅制限に到達した動きは騰落率でなく「ストップ高/安」と書き、制限値幅の計算を示す。
7. 直近20営業日の前日比の絶対値平均を下回る動きはノイズと明記する。
8. 推定の日付（`is_estimate`）は、出すたびに「推定」と付ける。休場日に当たる推定日は書かない。
9. TOPIX の指数値はキーレスで取れない。`1306.T` を「上場投資信託によるプロキシ」と明記して使う。NT倍率は出さない。
10. 動きと原因を分ける。取得した見出しや開示が因果を明言する場合だけ因果を書く。
11. （訂正）の開示は新規の決算に数えない。
12. 取得できなかったものは「取得不可」の節に列挙する。穴を埋めない。
13. 開示資料の PDF は公開リポジトリに置かない。リンクは TDnet のものを貼り、期限があることを書く。
14. 末尾に固定の免責事項を置く（文面は `note-report-template.md`）。

## 8. 公開前の確認（チェックリスト）

- [ ] 題名に数字が入っている（会社別メモは会社名とコードも）
- [ ] 有料ラインが規定の位置にある
- [ ] 分解表の合計が一致する
- [ ] 会社予想との比較に「どの時点の予想か」（例: 7/9時点）が書いてある
- [ ] アナリスト予想に人数が付いている
- [ ] 推定日に「推定」が付いている
- [ ] 売買推奨・目標株価・格付け・断定表現がない
- [ ] 「取得できなかったもの」の節がある
- [ ] 出典にリンクと取得日時がある
- [ ] 免責事項がある
- [ ] 相互参照のリンクが貼ってある

## 9. ファイルの置き場所と名前

```
reports/
  article-rules.md                      # このファイル
  daily/note-daily-YYYY-MM-DD.md        # 日次記事（2026-10-10 以降の新規分）
  companies/<コード>/YYYY-MM-DD.md       # 会社別メモ（開示日）
```

- 過去の日次記事（`keyless-verification/note-daily-*.md`）は検証記録として動かさない。
- 開示資料の PDF は `~/.vibe-trading/imports/tdnet/<開示日>/`（リポジトリ外）。
